# Contributing

1. Read docs/planning/PRODUCT_PLAN.md and the task tracker before implementation.
2. Work on a descriptive feature branch such as feature/02-number-types-content or feature/03-ui-design-system.
3. Keep normal content separate from reusable UI and game behaviour.
4. Review maths accuracy, one correct answer per MCQ and accessible touch/keyboard interactions.
5. Run checks appropriate to the change. Do not claim CI or production verification without evidence.
6. Update task status and record the branch, commit or PR, checks and remaining work.
7. Open a pull request with the concrete change and validation. Never deploy as a side effect of editing content.

Framework-specific install, development and test commands will be documented when the stack is selected. No CI workflow is claimed or configured yet.
