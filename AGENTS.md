# Repository working instructions

Read README.md, docs/TASKS.md, docs/STATUS.md and docs/architecture/DECISIONS.md before changes.

- The product scope is docs/planning/PRODUCT_PLAN.md. Keep future features out of the first release.
- Use simple English for child-facing content. Optional Hindi help must not change the mathematical meaning.
- Natural numbers start at 1 here. Zero is whole and even; 0 and 1 are neither prime nor composite.
- Number families overlap; sorting games must not teach exclusive membership incorrectly.
- Provide tap and keyboard alternatives for drag games. Colour alone must not communicate correctness.
- No real child identities, student results, passwords, keys or production secrets in this public repo.
- Do not assume the stack, hosting or domain has been chosen. Record technical decisions before introducing dependencies.
- Keep task and status documents accurate; distinguish sample data, local checks, CI and production evidence.
- Implement on feature branches. Repository initialization is the only baseline work currently on main.
